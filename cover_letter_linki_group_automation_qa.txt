Як мій досвід лягає на ваш стек:

- Playwright + TypeScript. Маю живий E2E-сьют на Playwright з POM, фікстурами, стабільною ієрархією локаторів (data-testid > role > text > css), trace/video/HAR на падіннях і Allure-звітом у GitHub Pages: https://pyavchik.github.io/slotsone-playwright/. Покриває auth, ігровий флоу, історію раундів, провайдер-fair перевірку.
- API-тестування. REST/HTTP, генерація тест-даних, перевірка схеми та цілісності у відповідях; Postman із pre-request скриптами, ланцюжками оточень та ассертами — приклади: https://pyavchikstream.online/postman-tests.html. У Digicode писав API-автоматизацію (REST Assured) з нуля.
- Бази даних. PostgreSQL/MySQL — SELECT/JOIN/агрегації для звіряння стану беку з API та UI: https://pyavchikstream.online/sql.html. З MongoDB працював на попередніх проєктах (find/aggregate, перевірка документів після API-операцій).
- CI/CD. Jenkins та GitHub Actions — щоденно; GitLab CI — використовував на попередніх проєктах. Налаштовував джоби для regression/smoke, артефакти (Allure, trace, скріни), retry-стратегії, паралелізацію за shard'ами.
- Test management. Jira + TestRail як основні; Qase — інструмент того ж класу, ввімкнусь швидко (структура suites/cases/runs, інтеграція з CI через API/CLI, прив'язка автотестів до case ID).
- Web automation desktop + mobile. Cross-browser (Chromium/Firefox/WebKit), емуляція мобільних в'юпортів і реальні пристрої через DevTools/BrowserStack-сценарії.

iGaming-домен. У Innovation Group (2014–2019) — 5 років тестування HTML5-слотів, рулетки та карткових ігор: правила гри, paytable, RTP, адмінка, історія раундів, платіжні флоу, партнерські модулі та сертифікаційна документація. У Digicode (2019–2021) — онлайн-казино, повний цикл QA, UI/API-фреймворки з нуля, JMeter-навантаження на game server. У EG (2021–2025) — підтримка 1500+ автотестів. Паралельно веду власне iGaming-демо (слоти + рулетка) з повним циклом QA: бек на Node/Express + PostgreSQL, фронт на React/Vite, адмінка на Next.js — тримає мене в актуальному контексті по транзакційних системах, ledger-логіці та provably-fair.

AI / LLM / Claude API (ваш "nice-to-have", мій щоденний інструмент).

- Daily toolchain: Claude Code CLI (термінальний агент Anthropic) + Cursor AI. Найактивніший use-case — UI-автоматизація на Playwright/Selenium: генерація POM з DOM зі стабільною ієрархією локаторів, скаффолдинг spec-файлів з тест-кейсів або Gherkin, рефакторинг хелперів по всій кодбазі, дебаг flaky-тестів через trace/video/логи, тюнінг auto-wait/retry.
- Поза UI: генерація чек-лістів та negative/boundary кейсів з OpenAPI, побудова Postman-колекцій зі Swagger, парсинг стек-трейсів / HAR / серверних логів для локалізації root cause, SQL для верифікації даних, тест-документація у форматі TestRail/Jira.
- Training AI testing systems / knowledge bases. На власних проєктах будую rules-файли (CLAUDE.md / .cursorrules) і memory/knowledge bases для агента — кодстайл, патерни локаторів, вимоги до тест-документації, домен-специфічна логіка (RTP, ledger, idempotency). Це і є "minimal-intervention AI QA pipeline" — агент рутинно генерує/підтримує тести, людина тримає архітектуру і review.
- Принцип: AI бере на себе boilerplate і рутину, архітектура і review — за мною.
