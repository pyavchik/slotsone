Як використовуєте AI в тестуванні? — розгорнута відповідь

AI для мене — робочий інструмент, а не експеримент. Основний стек — Claude Code CLI (термінальний агент від Anthropic) + Cursor AI. Нижче — як саме використовую в QA-флоу.

1. UI-автоматизація через Claude Code CLI (основний use-case)

Я будую й підтримую Playwright/Selenium-фреймворки в парі з Claude CLI прямо в терміналі проєкту. На практиці це виглядає так:

- Генерація Page Objects із live-сторінки. Відкриваю сторінку, даю Claude CLI HTML/DOM або скріншот, він пропонує стабільні локатори (data-testid > role > text > css), розкладає їх у POM із типізацією (TS). Я валідую, правлю нестабільні селектори.
- Скафолдинг тестів із тест-кейсів. Кидаю йому тест-кейс у Gherkin / табличному вигляді — отримую готовий spec-файл із фікстурами, хуками, очікуваннями. Далі сам доводжу до production quality (асерти, data-driven, тайм-аути).
- Рефактор і дедуплікація. «Знайди всі місця, де ми чекаємо toast, і винеси в helper» — Claude CLI бачить усю кодову базу і робить послідовний рефактор по всіх spec-ах, а не в одному файлі.
- Розбір flaky-тестів. Скидаю йому trace/video/лог → він локалізує, де саме race condition чи неправильне очікування, і пропонує фікс (auto-wait, network idle, retry policy).
- Інтеграція в CI. GitHub Actions / Jenkins-конфіги, Docker-обгортки для ранерів, паралелізація шардами — теж через нього.

Ключове: я не копіпащу — я рев’ю, правлю й тримаю відповідальність за фінальний код. AI прискорює рутину (boilerplate, локатори, репорти), а архітектурні рішення — мої.

2. Тестова документація й test design

- Генерація чек-лістів і тест-кейсів із вимог / Figma / API-специфікації (OpenAPI → негативні кейси, boundary values, equivalence partitioning).
- Рев’ю bug report’ів — AI дає другий погляд на severity, reproduction steps, missing info.
- TestRail/Jira-формат із markdown за 1 prompt.

3. Аналіз логів і дефектів

- Вставляю stack trace / network HAR / серверний лог → отримую гіпотези root cause з посиланням на конкретні рядки. Особливо корисно на клієнт-серверних багах, де потрібно зіставити frontend-подію з backend-логом.
- SQL-діагностика: формулюю «знайди всі замовлення з неконсистентним статусом» — Claude CLI пише запит під мою схему.

4. API-тестування

- Генерація Postman-колекцій з OpenAPI-специфікації, автоматичне заповнення негативних сценаріїв, контрактних перевірок.
- Mock-дані, тестові payload’и, JWT-токени для фікстур.

5. Пет-проєкти як polygon

На electro-motors.com, bestprice.com.ua та iGaming-демо я цей флоу обкатую end-to-end — від генерації POM до CI. Тому можу показати живі артефакти, а не «теорію».

Межі відповідальності AI: він не вирішує, ЩО тестувати і які ризики пріоритетні — це залишається за QA. Він прискорює «як» і «скільки».
